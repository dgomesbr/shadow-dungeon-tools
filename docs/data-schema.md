# web/public/data — generated data schema

Generated by `pipeline/build-data.mjs` (`cd pipeline && npm install && npm run build`).
Source: the SaveTool extraction at
`%USERPROFILE%\AppData\LocalLow\OO Cat\ShadowDungeonSaveTool\assets\extracted\`
(override with the `SD_EXTRACTED_DIR` env var). Do not hand-edit the output.

Source `.bin` tables are plain CSV, GBK/GB18030-encoded. The pipeline parses
them at the byte level (comma/quote/CRLF are never valid GBK trail bytes, so
column alignment survives the partially corrupted Chinese columns), decodes
per-field, coerces numerics, and drops the Chinese name/label columns — the
English `ItemName`/`IndexName` columns are the canonical keys.

## Formats

* Tables with more than 200 rows are **column-oriented**:
  `{"cols":["A","B",...],"rows":[[a,b,...],...]}` — `weapons.json`,
  `procs.json`, `skills.json`.
* Everything else is a plain **array of objects**.
* English strings are inline; they double as the i18n key. Other languages are
  in per-locale packs under `i18n/`, meant to be loaded on demand (the web app
  currently renders English only and fetches none of them).

## Shared enums

| Enum | Values |
|---|---|
| `EL` / `damageType` (element) | 0 Fire, 1 Frozen, 2 Thunder, 3 Poison, 4 Physics, 5 Shadow |
| `Quality` (weapons) | 0 Normal, 1 Magic, 2 Rare, 3 Exquisite, 4 Epic, 5 Legendary, 6 Mythical (gold). Values >6 appear only on gems/consumables, which use their own scale. |
| `CharType` (equipment slot) | 0 bone, 1 corpse, 2 head, 3 body, 4 hand, 5 leg, 6–9 accessories ("little"). 0/1 are the main/off-hand pair. |
| `Xi` (class id) | 0-based row index into `classes.json`. 0 Hell Messenger … 11 Corrupt Priest (the poison/"Necromancer" class), 12 Paragon Talents (paragon tree, not playable). |

## weapons.json — 3,440 rows, column-oriented

All weapon/equipment templates from `0_0_Weapon.bin`. `GlobalID` is unique.
Icon identity for the sprite atlas is the tuple **(PLtype, CharType, Quality,
GlobalID)**; `IconType`/`Icon` are the table's own icon indices.

| Column | Meaning |
|---|---|
| `GlobalID` | Primary key. Set armor uses 20000/30000/40000/50000 + SetID + 289 (head/body/hand/leg). |
| `ItemName` | English name; i18n key into `i18n/*.json`. |
| `DropLevelStart` | Minimum drop level. |
| `Quality` | 0–6, see enum. |
| `SizeX`, `SizeY` | Inventory footprint on the 15×17 grid (width, height in cells). |
| `CurAocaoCount` | Gem socket (Aocao) count. |
| `IconType`, `Icon` | Icon sheet/index used by the game's ItemManager. |
| `PLtype` | Icon/armor group: 0–3 (ItemManager has 4 `GP` groups; set armor is 3), 1000 for accessories. |
| `WeaponType` | String: staff, spell, sword, shield, bow, arrow, bone, corpse, head, body, hand, leg, little. |
| `CharType` | Equipment slot, see enum. |
| `DMG`, `Heal`, `Mana`, `EL` | Base stat block. Interpretation depends on slot: `DMG` is weapon damage on main-hands (block-ish on shields), `Heal`/`Mana` are health/mana stats on armor, `EL` is the elemental value (damage% on weapons / pen% on off-hands / resist% on armor — the save materializes it into the per-element `Fire..Shadow` fields). Not fully verified; emitted raw. |
| `MainID` | Row `ID` into `affixes.json` pool `main` (which main affixes this item can roll). 100% referential. |
| `DotID` | Row `ID` into pool `dot`. 100% referential. |
| `SkID` | Row `ID` into pool `sk`. 100% referential. |
| `Affixes` | Fixed main-affix rolls: array (max 7) of `[Index, EL, NB]` triples, trailing empties trimmed. Same shape as the save's `WPDT_A`. |
| `SkillAffixes` | Up to 2 groups `[SkName, Index, ID, EL, NB, Link]`. In templates these are always numeric (SkName 0); only `NB` is populated — meaning unconfirmed (likely roll counts). Emitted raw. |
| `Sockets` | Fixed weapon-skill sockets (WPSK): array (max 6) of `[skillIndexName, points]`. `skillIndexName` joins `skills.json` `IndexName`. |
| `SPC` | Proc id into `procs.json` `ID` (0 = none). The source table stores 3 slots but they are identical on every row, verified at build time. |
| `Set` | `SetID` into `sets.json` (0 = not part of a set). |

Dropped from the source: the 2 Chinese name columns, `SoundDrop`, `SoundUse`,
`RotateType`, all Chinese group labels.

## gems.json — 137 rows

`0_2_Baoshi.bin`. Fields: `GlobalID`, `ItemName`, `Price`, `Quality`
(gem scale, up to 8), `Icon`, `Level`, `UseType` (0 socketable gem,
1 JH/enhance, 2 stones, 3/4 runes — rune templates are looked up by
`SKname`/`Index` by the save sanitizer, 5 other), `BS_Quality`, `Bstype`
(color/effect key: red/blue/yellow/green/white/purple, `JH*`, `Stone_*`,
`FW_SK`/`FW_SPC`, stat keys like `DMG`, `ATS`, `DOT`…), `Number` (effect
magnitude), `MstackSize` (max stack), `CstackSize` (default stack),
`FWType`, `DropScene`.
Dropped: sounds, `RotateType`, `DropSpriteSize`.

Known item: Legendary Ruby = `GlobalID` 50001, `Bstype` red, `Number` 10.

## useitems.json — 88 rows

`0_3_UseItem.bin` (potions/consumables). Fields: `GlobalID` (60000+),
`ItemName`, `Price`, `Quality`, `Icon`, `Level`, `InfoType` (tooltip
template 0–7), `UseType` (string effect key: health, mana, EL_Damage,
fire…shadow, hammers, mirrors, keys, …), `damageType`, `Number` (effect
value), `CDTime`, `Duration`, `MstackSize`, `CstackSize`, `DropScene`.
Dropped: sounds, `RotateType`, `DropSpriteSize`.

## sets.json — 61 rows

`0_5_Set.bin` (row `SetID` 0 is the "none" placeholder). Per set:

* `SetID`, `SetName` (i18n key).
* `bonuses[3]` — bonus tiers `{MTP, SkN, Index, ID, EL, NB, LinkSK}`.
  `MTP` = pieces required to activate the tier, `SkN` = granted/boosted skill
  name (joins `Skill_FY`/i18n), `Index`/`ID`/`EL`/`NB` = affix-style effect
  tuple, `LinkSK` = linked-skill flag ("Link" placeholder in current data).
* `buff` — set proc buff: `{BuffName (i18n key, Buff_FY), BuffType, BuffTime,
  LayerMax, TP_Layer, NumberL, TP_Max, NumberM}`.
* `pieces` — **derived**: `[head, body, hand, leg]` armor `GlobalID`s
  (`20000/30000/40000/50000 + SetID + 289`), emitted only when all four exist
  in `weapons.json` (true for all 60 real sets). Necromancer-flavor sets are
  `SetID` 46–60; every piece row has `PLtype` 3 and `Set` = SetID.

## affixes.json — 201 rows

`1_0_Main.bin` + `1_1_DOT.bin` + `1_2_SK.bin` merged, discriminated by `pool`:

* `{pool:"main", id, entries:[[Index, EL, NB], ...]}` — 86 rows. The main
  affix pool a weapon's `MainID` points at; each triple is one rollable stat
  (Index = stat id, EL = element where relevant, NB = magnitude).
* `{pool:"dot", id, entries:[[Index, EL, NB], ...]}` — 66 rows. DOT affix
  pool (`DotID`). DOT `Index` values are ≥2000. For bool-effect indexes
  **{2001, 2005, 2100, 2102, 2200, 2201, 2301, 2302, 2304, 2400, 2604}** the
  `number` is ignored by the game (presence = on). DOT numbers are floored to
  int at runtime.
* `{pool:"sk", id, entries:[{SkN, Inx, ID, EL, NB, Link}, ...]}` — 49 rows.
  Skill-affix pool (`SkID`): `SkN` = affected skill IndexName (i18n key),
  `Inx` = effect index, `NB` = magnitude.

Trailing all-zero entries are trimmed; interior order is preserved.

## procs.json — 6,883 rows, column-oriented

`0_1_SPC.bin` (special/proc effects). The web app lazy-loads this file on
demand (only the item detail panel needs it); it is not part of the initial
catalog fetch. Kept columns: `ID` (primary key —
`weapons.json.SPC` points here), `TP`, `FW`, `name` (i18n key into `SPC_FY`,
e.g. "ORB_Ball_A"; a handful of internal names like `SM` have no
localization), `FStp`, `LockType`, `inf`, `Pri`, `SKName` (parent skill
IndexName, joins `skills.json`/i18n), `ZQName`, `RTy`, `Dis`, `Rat`, `DMG`,
`DMG_A`, `DMG_B`, `ThrT`, `ATT`, `ATT_A`, `ATT_B`, `No`, `BF`, `DF`.
The remaining ~80 source columns (ORB/EXP/FX/projectile geometry/sound) are
engine-only and dropped.

Save-side gotcha: an orb's damage is `SPC[].PRC × SPC_DMG_Bei/100`; `PRC`
lives in the save, 100 is the neutral multiplier.

## skills.json — 398 rows, column-oriented

Talent-tree skills, merged from `0_SampleF` (71), `1_SampleS` (180),
`2_CompF` (13), `3_CompS` (39), `4_DotF` (12), `5_DotS` (48), `6_Bei` (36).
These are what weapon `Sockets` and the save's `WPSK`/`XiData` reference.

| Column | Meaning |
|---|---|
| `IndexName` | Primary key + i18n key (`Skill_FY`). |
| `src` | Source table: `sampleF` (active skills), `sampleS` (skill upgrades), `compF`/`compS` (companions + upgrades), `dotF`/`dotS` (DOT skills + upgrades), `bei` (multiplier passives). |
| `Xi` | Class id (0–11), joins `classes.json`. Each class has 33–34 skills; Xi 11 (Corrupt Priest) has the 34 poison/"Necromancer" skills. |
| `Level_Max` | Max skill level. (The save's `Level_Base` is the player's invested points — there is no `Level_Base` column in the tables.) |
| `UnLock_Point` | Points required to unlock. |
| `Price` | Point cost. |
| `icon` | Icon index in the skill icon atlas. |
| `damageType` | Element (see enum); `null` for `compS` rows (column absent in that table). |
| `Info` | Description key into `Skill_FY` (e.g. `info_FireBall`). Descriptions are not included in the i18n packs (names only) — resolve against the source `Skill_FY.json` if ever needed. |

`0_4_Skill.bin` (combat-engine skill instances, same 103-column layout as
`0_1_SPC.bin`) is intentionally **not** emitted — it contains projectile/FX
engine parameters, not item-UI data.

## classes.json — 13 rows

`Xi.bin`. `{id, IndexName, icon, Level_Base, damageType, Number}` where `id`
is the 0-based row index (this is the `Xi` value used everywhere else),
`IndexName` is the i18n key, `damageType` the class element (Corrupt Priest =
3 Poison), `Number` a class-wide multiplier (0.3 for all).

## i18n/&lt;locale&gt;.json — ~4,770–4,830 keys each

Flat `{ englishKey: localizedString }` maps for: item names (weapons, gems,
useitems), set names, set bonus skill names, set buff names, sk-pool affix
skill names, talent skill names, class names, proc names (`SPC_FY`), and
proc parent-skill names. Entries identical to the English key are omitted —
**fall back to the key itself** when a lookup misses.

Locales: `zh-CN, zh-TW, ru, de, fr, pt-BR, pt-PT, pl, ko, es-ES, es-419, tr,
cs, sv, it, nl, uk, th, hu, da, ja, el, fi` (English is inline in the data).

Sources searched in order: `Item_FY`, `Skill_FY`, `SPC_FY`, `Buff_FY`.
6 internal proc names stay unresolved (XJL_CN, XJL_SH, XJL_XJ, SK_Ball_F,
LK, SM) — the UI should show the raw key or hide them.

`MainDisplay_FY`/`Main_FY` (affix display templates like
`MainStat_PlainPercent`) are keyed by semantic label, not by affix `Index`;
the Index→template mapping lives in game code, so affix display strings are
not emitted yet.

## meta.json

`{generatedAt, game, sourceTables:{file:rowCount}, outputs:{file:{rows,bytes}},
i18n:{locales, keysResolved, keysUnresolved}}`.

## affix-names.json

Also under `web/public/data/`, but not produced by `build-data.mjs`: the
affix Index → English tooltip-template map the web app uses to render
game-faithful affix lines. Schema and provenance in
[affix-mapping.md](affix-mapping.md).

## Join keys at a glance

| Key | From → To |
|---|---|
| `GlobalID` | save `WeaponSaveData`/`Baoshi`/`UseItem` → `weapons`/`gems`/`useitems`; `sets.pieces[]` → `weapons` |
| `IndexName` | weapon `Sockets[i][0]`, save `WPSK[].IndexName`, `XiData[].IndexName`, proc `SKName`, affix `SkN` → `skills.json` |
| `SetID` | `weapons.Set`, save `Set_Index` → `sets.json` |
| `Xi` | `skills.Xi` → `classes.id` |
| `SPC` id | `weapons.SPC` → `procs.ID` |
| `MainID`/`DotID`/`SkID` | `weapons` → `affixes` (`pool` main/dot/sk, field `id`) |
| English string | any inline name → `i18n/<locale>.json` key (fallback: the key) |

## Mapping the save onto these tables

Saves are OdinSerializer binary (see `docs/sav-binary-format.md`); the fields
below appear in the SaveTool JSON dump.

**WeaponSaveData** (equipped: `Equipments[10]`, indexed by `CharType` 0–9;
inventory: `ContainerItemSaveData` wrappers with `ItemType` 0):

* `GlobalID`, `Quality`, `PLtype`, `CharType` → template row + icon tuple
  (PLtype, CharType, Quality, GlobalID). Editors should keep Quality ≤ 6.
* `SizeX/SizeY` footprint from the template governs grid placement
  (15×17 inventory pages; the game silently drops overlapping/out-of-range
  items and does **not** footprint-validate — the editor must).
* `Fire, Frozen, Thunder, Poison, Physics, Shadow` — materialized elemental
  values: damage% on main-hands (acc slots 7/9), pen% on off-hand (acc 8),
  resist% on armor (acc 6). Template `EL` is the pre-roll base.
* `Main` / `DOT` — arrays of `WPDT_A {Index, EL, number}`, exactly the
  `[Index, EL, NB]` triples of `affixes.json`; applied verbatim, no clamps
  (only runtime caps: DR ≤ 95, block ≤ 100). Bool DOT indexes ignore `number`.
* `WPSK[6]` — `{IndexName, Number, Number2, price}` skill sockets;
  `WP_SkillCount` = populated count. `IndexName` joins `skills.json`; points
  only amplify skills the player has invested in (`XiData[].Level_Base` ≥ 1).
* `Aocao` gem sockets — `Type` 0–25 maps to the game's `GemFloatFields`
  (e.g. 12 = PoisonDamage_Bei); socket count comes from `CurAocaoCount`.
* `SPC[]` — proc instances; `PRC` multiplies with `SPC_DMG_Bei/100`
  (multiply only `PRC` when editing, never both).
* `Set_Index` → `sets.json.SetID`; alone activates set bonuses
  (`SetRuntimeData` null is fine).

**Baoshi** (gems in inventory/chest): `GlobalID` → `gems.json`;
`CstackSize` = current stack count, cap edits at the template's
`MstackSize`; `Index`/`SKname` are the template keys the sanitizer checks
for UseType 3/4 runes (safe to duplicate across clones).

**UseItem** (consumables): `GlobalID` → `useitems.json`; `CstackSize` =
current stack, cap at `MstackSize`. Items with `MstackSize` 1 renormalize —
give quantity as multiple 1-stack clones instead.

## Known uncertainties

* Weapon `DMG/Heal/Mana/EL` per-slot semantics are inferred, not decompiled.
* Weapon `SkillAffixes` groups: only `NB` is ever non-zero in templates;
  exact meaning (likely affix roll counts) unconfirmed.
* `procs.json` short column names (`TP`, `FW`, `FStp`, `RTy`, `Rat`, `ThrT`,
  `ATT`, `No`, `BF`, `DF`…) are engine flags whose exact meaning is not
  documented; kept because they are gameplay data (damage/rate/attack type).
* Gem/useitem `Quality` values 7–8 exceed the weapon 0–6 scale (separate
  rarity scale for non-equipment).
